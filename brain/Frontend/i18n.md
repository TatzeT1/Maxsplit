# i18n — German-first, single dictionary

Dictionary: `src/lib/i18n/de.ts` (canonical) and `src/lib/i18n/en.ts` (structural mirror).
Lookup: `src/lib/i18n/translate.ts`. Server helper: `src/lib/i18n/server.ts`. Client:
`src/components/locale-provider.tsx` (`useT()`).

## German is the product, English is a type-checked shadow

Per AGENTS.md's origin brief: **UI language is German only (de-DE)**, "du" not "Sie," friendly
short tone, no corporate speak. `de.ts` is the dictionary that was actually designed for the
product. `en.ts` exists so the *type* `Dictionary` (every leaf of `de`'s shape widened to
`string`) has a second implementation to check against — don't assume English is a maintained,
product-reviewed translation; treat it as "keeps the type honest," not "ships in production
with the same care."

## No hardcoded strings, ever

> [!warning] Every user-facing string goes through `t()`. No exceptions.
> This "costs almost nothing now and means adding a locale later is a new file, not a
> refactor" (README). If you're writing a component and reaching for a literal German string,
> stop — add the key to `de.ts` (and the matching key to `en.ts`) instead.

Code, comments, variable/function names, commit messages, and this vault itself stay
**English** — only the `de`/`en` dictionaries and their values are the translated surface.

## `TranslationKey` — compile-time dot-path safety

`translate.ts` derives `TranslationKey` as a mapped/conditional type over `typeof de` — every
valid `"section.key"` dot-path through the dictionary, computed automatically from `de.ts`'s
actual shape. Add a key to `de.ts` and it's immediately a valid, autocompletable
`TranslationKey` everywhere `t()` is called; no separate type to hand-maintain. `resolve()`
throws at runtime if a path doesn't resolve to a string in the given locale — a missing key in
`en.ts` (if `en.ts` has drifted out of sync) fails loudly rather than rendering `undefined`.

## Interpolation

`translate(locale, key, vars)` replaces `{{placeholder}}` tokens: e.g.
`t("balances.youOwe", { name: "Anna", amount: "12,50 €" })`. Note `amount` is passed in
**already formatted** — formatting money/dates is a separate concern (`src/lib/format/`),
never done inline inside a translation string.

## Locale resolution: cookie-backed, server + client

`LOCALE_COOKIE`, `DEFAULT_LOCALE = "de"`. `getLocale()`/`getServerT()`
(`src/lib/i18n/server.ts`) read the cookie server-side for Server Components (e.g.
`generateMetadata` in `app/layout.tsx`, the settlement PDF route). `LocaleProvider` +
`useT()` mirror the same resolved locale to client components. `language-toggle.tsx` is the
only UI that changes it.

## German formatting rules (from AGENTS.md's origin brief — still binding)

- `Intl.NumberFormat('de-DE')` / `Intl.DateTimeFormat('de-DE')` only — never hand-rolled
  formatting of numbers, currency, or dates. See `src/lib/format/date.ts` and
  `src/lib/format/money.ts`.
- Money renders as `1.234,56 €`; dates as `12.08.2026`; weekdays `Mo–So`.
